# Plugin Store promo images

Marketing images for the Subscribr listing on the Craft Plugin Store, rendered in the same theme as
the plugin's marketing page at
[justinholt.com/plugins/craft-subscribr](https://justinholt.com/plugins/craft-subscribr).

## Building

```bash
./build.sh          # all slides
./build.sh "2 9"    # just slides 2 and 9
```

Output lands in `out/` as `subscribr-promo-N.jpg`, 1920×1080 (rendered at 2× in headless Chrome,
then downsampled so the type stays crisp).

## Screenshots

`shots/` holds real captures from a Craft 5 install running Commerce 5 and Subscribr Pro — not
mockups. `seed-demo.php` builds the store they are taken from:

```bash
docker exec -w /var/www/html ddev-plugin-testing-web \
  php /var/www/craft-subscribr/promos/seed-demo.php            # build
docker exec -w /var/www/html ddev-plugin-testing-web \
  php /var/www/craft-subscribr/promos/seed-demo.php --teardown  # remove it again
```

Two things about that script are deliberate:

- **Renewals are driven at the date that was due**, not at `now`. Back-dating a subscription and
  then sweeping it today is exactly the case the catch-up guard exists to refuse — it abandons the
  missed cycles and jumps the schedule forward, and the screenshots come out empty.
- **The rows it writes are then re-stamped with the dates they describe.** A ledger whose every
  entry is timestamped today reads as a fixture, which is the opposite of what a screenshot from a
  live install is for.

Captures are taken at a 1400px layout width with the page zoomed 2×, cropped to `#main`, with the
sidebar and the other plugins' banners removed — the testing install has 130 plugins in it and most
of them have something to say.

A tall capture is dropped into `.cpc-frame.cpc-clip`, which anchors it to the top and fades the cut;
the interesting rows are always the first ones.

## Editing

Everything lives in `slides.html` — one `<section class="slide">` per image. The palette and fonts
are the plugin site's: accent `#e58a32`, Jersey 20 for display, Inter for body.

`assets/` holds the fonts and two icon files:

- `icon.svg` — the app icon, used for the cover mark and the footer lockup. Copy it from
  `../src/icon.svg` whenever the icon changes.
- `watermark.svg` — the icon redrawn as line art. The icon's header bar is a solid slab; at
  watermark scale it is a ~670px grey block across the slide and reads as a mistake rather than as
  a mark, so every filled shape is outlined instead.

`fonts.css` is generated by `build.sh` (the woff2 files are base64-inlined so Chrome's `file://`
origin rules can't block them) and is not checked in.
