The whole idea
Commerce asks the gateway Do you implement subscriptions? Subscribr asks a smaller question Can you store a card?

The first question has one affirmative answer in practice. The second is true of nearly every gateway ever written for Commerce — and a gateway that can’t store a card still carries subscriptions, by invoice.

Gateways

Your gateway,
not ours

Nothing special-cases Stripe. A Stripe gateway is just a gateway with payment sources.

  • Stored card? It renews by itself, off-session
  • No stored card? An emailed link drops the renewal into your own checkout
  • A gateway screen tells you which you have, before you commit
Stripe Braintree Authorize.net Mollie Opayo Worldpay Square Adyen Paystack eWAY …and the rest

The test is supportsPaymentSources() plus supportsPurchase() — not an interface only one gateway implements.

Mixed carts

One cart,
both kinds

A recurring line is an ordinary line item carrying one option key. Buy a bag once and subscribe to the same bag, in the same basket.

  • No bespoke cart, no second checkout
  • Commerce de-duplicates on the options hash, so the two lines stay apart

Trials, joining fees and prepayment are adjustments, so the customer still sees what they signed up for at its real price.

Self-service

Booked,
not applied

Self-service is mostly “do this next time”, not “do this now”. A booking is a row, consumed at the cycle boundary.

  • Changing your mind means cancelling a booking
  • One place decides what a cycle is supposed to be

Pinned items are deleted when the cycle renews, so the month after goes back to normal by itself.
